# Дашборд аналитики маркетплейсов — Мебель

Streamlit-дашборд для сведения продаж Ozon и Wildberries в нише «Мебель»
(стулья, столы, диваны): KPI, динамика, продажи по категориям, реклама
(ДРР) и юнит-экономика.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется в браузере по адресу `http://localhost:8501`.

## Как это работает

- **Без API-ключей** дашборд сразу показывает реалистичные тестовые
  данные из `modules/mock_data.py` (селлеры «Лебедев», «Госович»,
  артикулы `MASON-A-02-14-1`, `NORD`, `PIXEL` и др.) — можно сразу
  оценить интерфейс.
- **С API-ключами** (вводятся в сайдбаре) дашборд пытается получить
  реальные данные через `modules/ozon_api.py` и `modules/wb_api.py`.
  При ошибке (нет ключа, 401/403, 500, сетевая ошибка или неожиданный
  формат ответа) дашборд выводит предупреждение и безопасно
  переключается на тестовые данные — приложение никогда не падает.
- **Себестоимость** загружается файлом (.xlsx/.csv) с колонками
  `Артикул` и `Себестоимость` в сайдбаре. Без файла используется
  дефолтный справочник из `mock_data.py`.

## Структура проекта

```
app.py                    — интерфейс Streamlit (сайдбар, KPI, таблицы, графики)
modules/ozon_api.py        — клиент Ozon Seller API (FBO/FBS/финансовый отчёт)
modules/wb_api.py          — клиент Wildberries API Статистики
modules/data_processor.py  — KPI, юнит-экономика, объединение с себестоимостью
modules/mock_data.py       — генератор тестовых данных
requirements.txt
```

## Важно про реальные данные API

Поля ответов Ozon/WB могут отличаться в зависимости от контракта и
версии API продавца. Функции `transform_ozon_postings` и
`transform_wb_sales` в `modules/data_processor.py` делают
best-effort маппинг в единую внутреннюю схему — при несовпадении
полей автоматически используются тестовые данные (см. выше). Если
структура ответа вашего кабинета отличается, скорректируйте эти
функции под реальный JSON.
